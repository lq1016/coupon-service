025 步体验路径

① 登录鉴权

user1 / admin 登录换取 JWT，后续请求统一带 Authorization: Bearer <token>。

200 完整 JWT + 用户信息

② 领券成功 + 幂等重放

领券返回券码与 status: unused；同幂等键再领一次返回 replay:true 与同一券码。

200 幂等键重复只成功一次

③ 超领拦截 + 防超发

管理员把限领规则改成「同用户 1 张 / 同设备 1 张」，再分别用同用户换设备、换账号同设备领券；最后用只有 1 张库存的模板连抢 2 次。

429 CLAIM_LIMIT_USER 429 CLAIM_LIMIT_DEVICE 409 INSUFFICIENT_STOCK

④ 核销

核销后券状态变 used 并绑定订单号；换一张新券沿用同一订单号再核销，命中订单维度约束。

200 409 ORDER_ALREADY_USED

⑤ 退券回补

管理员退券后券状态变 refunded，库存按规则回补：claimed −1、redeemed −1、refunded +1。

200 库存回补规则生效

06核心设计

防超发 · 原子条件更新

扣库存不是「先查再扣」，而是一条原子 SQL：
UPDATE inventory SET claimed=claimed+1 WHERE template_id=? AND claimed<total
changes()===0 即已售罄。better-sqlite3 单连接同步事务保证同一时刻只有一个领取在改库存，1 万张券绝不会被领走 10001 张。

幂等 · 双保险

每次领券要求客户端传全局唯一的 idempotencyKey。先查 idempotency_records，命中即返回首次结果（replay=true）；写入时 claim_records.idempotency_key 唯一约束作第二道防线。

防刷 · 可配置限额

每个模板有 anti_abuse_rules，按 user / device / ip 配置领取上限，超限分别返回 CLAIM_LIMIT_USER / CLAIM_LIMIT_DEVICE / CLAIM_LIMIT_IP。管理员可通过 PUT /api/templates/{id}/anti-abuse 动态调整。

状态机 · 退券回补

四态流转 unused→used（核销）、used→refunded（退券）、unused→expired（过期扫描）。退券时 inventory.claimed-1、refunded+1、redeemed-1，券实例置 refunded；过期时 claimed-1、expired+1。
